# MVO Test Results and Claim Validation

**Date:** 2026-02-25
**System:** Topology Brain Minimum Viable Organism
**Test:** A/B comparison: flat memory (System A) vs topology (System B) on 10 diverse-domain inputs + 5 cross-domain queries

---

## Test Setup

- 10 input texts across security, cooking, investing, ecology, teaching, architecture, music, medicine, game design, philosophy
- Inputs seeded with hidden cross-domain structural parallels (layering, controlled surrender, scaffolding, distributed memory, emergent complexity, compounding/decay)
- System A: Sonnet summarizes each input → appends to flat memory.md → queries use full memory as context
- System B: Haiku decomposes into concepts+facets → Sonnet traces chains between facets → 2% decay per run → Sonnet compares topology states → queries use topology as context
- Both use Sonnet for final query answering with identical prompts (only context differs)

## Honest Assessment: What Was Actually Proved

### What the test DID prove

1. **The plumbing works.** Decompose extracts meaningful concepts with facets. Connect traces plausible chains between them. Decay reduces weights correctly. Compare produces coherent diffs. The engineering is sound.

2. **Structured context produces structured output.** System B's query answer referenced specific facet domains and chain paths. System A's answer was good prose. This is unsurprising: structured input → structured output is a known LLM property.

3. **The LLM is very willing to find cross-domain connections when asked.** 275 cross-input chains from 10 inputs. But these were all explicitly generated by Sonnet in connect calls. They didn't emerge from trace accumulation.

### What the test DID NOT prove

1. **Emergence.** Every chain was directly generated by an LLM call asking "trace a connection between these two facets." No chain appeared that wasn't explicitly solicited. The topology accumulated LLM-generated connections. It didn't produce emergent ones.

2. **Topology > monolithic LLM.** System A found the same core insights (layering, controlled surrender, restraint as mastery) with 17x fewer tokens. The topology added structural formatting but not qualitatively different understanding.

3. **Developmental trajectory.** We only ran 10 cycles. No chain was ever pruned. No concept deepened through repeated exposure. No shift in how the system connects things was observable.

4. **The core thesis.** The thesis is: "an AI system that traces association chains through faceted concepts and compares those chains over time produces qualitatively different reasoning than flat memory accumulation." After this test, the answer is: **not proven.** The topology produced differently-formatted reasoning, not differently-derived reasoning.

## The 14 Claims and Their State of Proof

These claims come from `structural-paradigm-exploration.md` and related design documents. Each is assessed honestly against the MVO test results.

### Claim 1: Decomposed reasoning outperforms monolithic reasoning
**Source:** SPE lines 40-47, 276
**Claim:** Small reliable LM operations composed by code beat one big unreliable inference. Evidence: SkillsBench +18.8pp for moderate skills, mini-swe-agent superseding swe-agent, Claude's 95% reliability on narrow tasks vs 20% on whole-process introspection.
**MVO Result:** NOT TESTED. We didn't give System A the same task decomposition. We gave it a summarize-and-append pipeline. A fair test would compare the same query answered by (a) one monolithic Sonnet call with all 10 inputs, (b) the topology-mediated answer, (c) a chain-of-thought decomposition without topology.
**Status: UNVALIDATED**

### Claim 2: Critical density threshold for emergence
**Source:** SPE lines 133-137
**Claim:** The topology needs a critical mass of dots and traversals before emergent connections appear. Below that mass, you're building a database. Above it, connections emerge that nobody planted. Predicted threshold: agent density ≈ 0.23 from stigmergy research.
**MVO Result:** NOT TESTED. All 275 chains were planted by explicit LLM calls. We have no mechanism to detect unplanted connections. We don't know what "density" means in our system (facets per concept × traversals per unit?). 10 runs is almost certainly below any meaningful threshold.
**Status: UNVALIDATED (requires fundamentally different test design)**

### Claim 3: Phase transitions between Code/Language/LM
**Source:** SPE lines 92-117
**Claim:** The three primitives are phases of the same substance. Code = frozen (deterministic). Language = liquid (contextual). LM = gaseous (probabilistic). Agents should transition between phases based on uncertainty × stakes. Current agents are permanently in gas phase.
**MVO Result:** NOT BUILT. The circuit runs a fixed pipeline: always LM for every operation. No uncertainty measurement, no phase selection, no transition triggers.
**Status: UNVALIDATED (not in MVO scope)**

### Claim 4: Traces must be structural, not informational
**Source:** SPE lines 347-348
**Claim:** A post saying "X connects to Y" is information requiring LM interpretation. A weighted edge in a graph IS structure that directly influences traversal. The first requires reasoning (unreliable). The second is mechanical (reliable).
**MVO Result:** PARTIALLY TESTED. The topology stores weighted edges (chains with confidence and weight). But these edges were generated as text by the LLM and parsed into structure. They don't mechanically influence traversal. The query just dumps the whole topology as text for another LLM to interpret. The "structure" is cosmetic, not functional.
**Status: PARTIALLY VALIDATED (storage is structural) / FAILED (usage is still informational)**

### Claim 5: Traces must compound
**Source:** SPE lines 349-350
**Claim:** If 500 agents discover X→Y, the connection should get structurally stronger. Forum posts don't compound; weighted edges do.
**MVO Result:** MECHANISM EXISTS, NOT EXERCISED. Re-traversal adds +0.05 weight. But with one agent and 10 runs, most chains were traversed exactly once. No meaningful compounding occurred. We can't assess whether compounding improves quality.
**Status: UNVALIDATED (needs multi-traversal or multi-agent test)**

### Claim 6: Traces must decay (and decay matters)
**Source:** SPE lines 351, 939
**Claim:** Decay makes stigmergy adaptive: outdated routes weaken, new routes emerge. Without decay, you get accumulation (the opposite of intelligence). 2% per run, prune below 0.1.
**MVO Result:** MECHANISM WORKS, EFFECT NOT OBSERVABLE. Decay ran every cycle. After 10 runs, the oldest chains have weight 0.98^9 ≈ 0.834, nowhere near the 0.1 prune threshold. Zero chains were pruned. We'd need ~110 runs to see pruning from a weight-1.0 chain. The claim that decay *improves quality* is untested.
**Status: CODE VALIDATED / CLAIM UNVALIDATED (needs 100+ run test)**

### Claim 7: Compare is the core value operation
**Source:** SPE lines 555-574
**Claim:** If compare doesn't produce genuine insight, nothing else matters. Compare should detect not just what changed but what the change REVEALS.
**MVO Result:** MIXED. Compare ran 10 times and produced verbose, often insightful text about what changed. But in 9/10 cases it was comparing "empty/small topology" vs "topology + new stuff". Trivially, stuff appeared. The interesting comparison (subtle shifts in bridge concepts, path reorganization) requires a mature topology with 50+ runs where new inputs modify existing connections rather than just adding new ones.
**Status: MECHANICALLY VALIDATED / VALUE UNPROVEN (needs mature topology)**

### Claim 8: Autopoietic loop (outputs modify generating conditions)
**Source:** SPE lines 143-167
**Claim:** The cycle LM generates → Code captures trace → Language updates self-model → Updated self-model shapes next LM generation approximates operational closure. The system becomes different because of what happened, not just records what happened.
**MVO Result:** NOT BUILT. No identity.md. No feedback from topology state into operation prompts. Each cycle's decompose/connect calls are independent of all previous cycles except through the topology state passed as context to connect. The system records what happened but doesn't become different.
**Status: UNVALIDATED (not in MVO scope)**

### Claim 9: Topology as dual-use structure (knowledge store + reasoning trace)
**Source:** SPE lines 917-929
**Claim:** The topology simultaneously stores what the system knows (concepts, chains) AND how the system reasoned (which chains traversed, in what order). No other agent has this. Compare operates on both simultaneously.
**MVO Result:** NOT TESTED. We stored knowledge (concepts + chains). But the reasoning trace aspect (which chains were traversed during a query, which paths were explored and rejected) isn't captured. The topology is a knowledge store only. The "dual-use" claim requires instrumenting query-time traversal.
**Status: HALF BUILT (knowledge) / HALF MISSING (reasoning traces)**

### Claim 10: Structured forgetting improves performance (AoT validation)
**Source:** SPE lines 387-395
**Claim:** Atom of Thoughts (NeurIPS 2025) proves that decomposing reasoning into DAGs and then contracting (discarding intermediate history) outperforms CoT, ToT, GoT across all benchmarks. "The system gets simpler as it gets smarter."
**MVO Result:** NOT BUILT. The topology only accumulates. No contraction, no structured forgetting, no simplification. After 10 runs it has 290 chains, all retained.
**Status: UNVALIDATED (needs contraction mechanism)**

### Claim 11: Learning = rearranging connections, not adding knowledge
**Source:** SPE lines 262-268
**Claim:** Like neural network weight changes: the topology is the "parameter space," learning is rearranging connections. Measurable as connection depth changes, domain-crossing frequency shifts, bridge concept movement.
**MVO Result:** NOT TESTED. We only measured final state after 10 inputs. We didn't track whether chains reorganized (same endpoints, different paths) across runs. The topology only grew; nothing rearranged.
**Status: UNVALIDATED (needs longitudinal tracking of chain evolution)**

### Claim 12: Active inference for operation selection
**Source:** SPE lines 171-194
**Claim:** Instead of a fixed circuit topology, the agent uses active inference (minimize Expected Free Energy) to decide which atomic operation to perform next based on its uncertainty landscape.
**MVO Result:** NOT BUILT. Fixed pipeline: decompose → connect → decay → compare every time, regardless of input or topology state.
**Status: UNVALIDATED (Level 5 feature, not in MVO scope)**

### Claim 13: Antagonistic architecture (builder vs pruner)
**Source:** SPE lines 214-222
**Claim:** Two LMs in structural opposition: one builds, one prunes. Dynamic equilibrium through tension, like biological agonist-antagonist muscles. Enforces excretion structurally.
**MVO Result:** NOT BUILT. Single pipeline, no antagonist.
**Status: UNVALIDATED (not in MVO scope)**

### Claim 14: Resolution as the unit of intelligence
**Source:** SPE lines 224-233
**Claim:** Intelligence measured by discrimination resolution: how fine-grained the agent's distinctions are. Resolution increases through topology refinement (more specific facets, more precise connections) without topology growth.
**MVO Result:** NOT MEASURED. We have no metric for discrimination resolution. Facets were generated at uniform granularity by Haiku regardless of how many times a domain had been encountered.
**Status: UNVALIDATED (needs refinement mechanism and resolution metric)**

## Key Honest Takeaway

The MVO proved the engineering works. It did NOT prove the thesis. The central question, whether topology produces intelligence that flat memory can't, remains unanswered because:

1. **Unfair comparison**: System B spent 17x more tokens than System A
2. **No emergence**: All connections were LLM-generated on demand, not emergent
3. **Too few cycles**: 10 runs is insufficient for decay, compounding, rearrangement, or threshold effects
4. **No feedback loop**: The system doesn't become different because of its history
5. **Structure is cosmetic**: The topology is dumped as text for query answering: the LLM reads it like a document, not traverses it like a graph

The next system must address these five failures directly.
